使用工具：AI agent（撰寫程式、啟動 PHP 內建伺服器、在內建瀏覽器中測試）
檔案：`menu.php`

## 第1輪：新增價格上限篩選

**我的指令：** 網址加上 `max` 參數可以篩選價格上限，例如 `menu.php?category=熱炒&max=200` 只顯示熱炒中 200 元以下的菜。沒有 `max` 參數時不限價格。

**AI 測試過程中遇到的問題：** 一開始用 Git Bash 測試，中文和 `<script>` 被轉壞（測試工具的問題，不是程式的問題），之後改用內建瀏覽器實際打開網址測試。

**AI 回報的修改內容（註解標示【新增】）：**
- 讀取 `max` 參數：用 `filter_var` 檢查是不是 0 以上的整數。沒有 `max`，或填了 `abc`、`-5`、`1.5`，`$max` 就是 `null`，代表不限價格
- 價格篩選：先用分類篩一次，再用 `$item["price"] <= $max` 篩第二次。「以下」包含等於
- 有設定 `max` 時，多顯示一行「價格上限：XXX 元以下」
- 沒有改動：菜單資料、分類篩選、`sumPrice()`、`htmlspecialchars` 防護、版面

**AI 回報的測試結果：**

| 網址 | 預期 | 結果 |
|---|---|---|
| `?max=100` | 3 道，$230 | ✅ |
| `?category=熱炒&max=200` | 只有三杯雞，$180 | ✅ |
| `?category=青菜` | 2 道，$180，沒有價格上限那一行 | ✅ |
| 不帶參數 | 5 道，$630 | ✅ |
| `?max=180` | 三杯雞（剛好 180）有出現 | ✅ |
| `?category=熱炒&max=100` | 顯示「這個分類沒有餐點」 | ✅ |
| `?max=0` | 沒有菜 | ✅ |
| `?max=abc`、`-5`、`1.5` | 當成不限價格，不報錯 | ✅ |
| `?category=<script>...` | 只顯示文字，沒有執行 | ✅ |

另外用 `php -l` 做語法檢查，沒有錯誤。

**AI 主動提出的問題：** 分類按鈕的連結沒有改，所以在 `?max=200` 的頁面點「熱炒」，網址會變成 `?category=熱炒`，價格上限會不見。因為指令說其他功能不要動，所以 AI 沒有改，而是提出來詢問。
